# 金字塔原理課程設計與驗收

本文件取代舊版情境優先課綱與 `interactive-pilot.md` 的控制台方案。課程資料在 `learning/curriculum.mjs`，各單元結論、學習目標、小節目標與應用情境均由同一份資料呈現。

核心結論：Agent 要完成任務，必須取得適當資訊、控制執行過程，並用證據確認成果；有了品質基準，才能評估效率與分工。

## 原則

- 一套教材，地圖是導航，不另設純簡報／實驗室模式。
- 單元先給核心結論與 2–4 個學習目標，再依小節目標操作案例，最後用新情境檢查能否運用。
- 跨單元動作前先呈現新單元結論與目標，避免直接執行而跳過學習方向。
- 操作必須改變情境圖中的資料或結果，且說明原因。
- 比較選項不是測驗，不設標準答案閘門；允許自由切換比較。
- 由具體動作直接推進情境，不提供上一頁／下一頁或方向鍵翻頁；所有章節仍自由進入。
- 無計分、關卡解鎖、完成認證。只保存最後閱讀位置。

## 章節

共 7 個單元、48 個情境，包含 7 個章末應用情境。

| 單元 | 主線 | 完成後應能做到 |
|---|---|---|
| 0 先看完整系統（4） | 全貌 | 指出來源、決策者、執行者與完成證據 |
| 1 讓任務能持續推進（7） | 能完成 | 解釋 loop；區分模型決策與工具執行；判斷繼續、停止與交接 |
| 2 讓每一步都有適當資訊（6） | 能完成 | 選取與檢索；壓縮與刷新；區分 context、state、長期記憶 |
| 3 讓失敗保持在可控制的範圍（8） | 能信任 | 區分查詢與寫入逾時；運用冪等、資料驗證、fallback 與人工介入 |
| 4 讓成果有可檢查的證據（11） | 能信任 | 先列驗收條件，再從 trace 取證；選擇程式或語意評估；建立回歸案例 |
| 5 用量測決定如何改善（6） | 能改善 | 找瓶頸；依品質基準比較輸入、呼叫、平行與模型分流 |
| 6 依任務需要決定如何分工（6） | 能改善 | 區分工具平行與多 Agent；定義交接與失敗狀態；比較收益與成本 |

## 技術驗收

- 每個頁面存在完整操作前／後資訊或至少兩條有回饋的分支。
- 每小節有具體目標，每單元有結論、目標與新情境應用。
- 舊 observability / evaluation 書籤對應合併後相同案例。
- 地圖所有入口、直接網址、動作推進、跨章及最終回地圖。
- 回到上一步精確還原上一個操作狀態，包含跨情境的結果及比較選項；初始狀態不可回退。
- 切換地圖、直接網址與刷新重設操作歷史；動作更新網址使用 replaceState，避免瀏覽器上一頁變成另一套互動回退。
- 閱讀位置可恢復；儲存失敗不阻擋閱讀。
- 360px 寬 CSS 以直向角色排列，桌面三欄；減少動態偏好不播放轉場。
- 建置不產生獨立 Slidev 頁面，不載入原控制台。

## 人工學習驗收

操作前能否理解任務？操作後能否指出什麼改變？章末能否用自己的話說出概念？自動測試與按鈕可用性不代表已通過這三個學習標準。
